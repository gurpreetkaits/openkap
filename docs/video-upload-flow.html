Controller 📡 Browser Extension Captures Screen
User clicks "Record" in the Chrome extension. MediaRecorder API captures the screen (and optionally camera) as WebM chunks. Chunks are streamed via POST /api/stream/upload/{sessionId}/chunk every few seconds.
Controller ✅ User Stops Recording → Complete Upload
POST /api/stream/upload/{sessionId}/complete — Remaining pending chunks are appended in order, a Video record is created in the DB, and background jobs are fired after the HTTP response is sent (non-blocking).
Background Jobs ⚡ Processing Pipeline Begins (in parallel)
Multiple jobs are dispatched simultaneously — isolated so one failure doesn't block the others.
🐰 Bunny CDN Path
  • UploadToBunnyJob → uploads raw WebM to Bunny
  • Bunny auto-encodes to HLS (240p→1080p)
  • Webhook POST /api/webhooks/bunny
  • Status: pending → uploading → processing → ready
💾 Local Storage Path
  • RemuxWebmJob → fixes WebM container headers
  • ConvertVideoToMp4Job → MP4 with faststart
  • ProcessHlsConversionJob → HLS segments
  • Status: pending → processing → completed
Background Jobs 🧠 AI / Metadata Enrichment
Runs alongside encoding — jobs auto-reschedule if the media isn't ready yet.
  • GenerateThumbnailJob → captures a frame at the video midpoint
  • GenerateTranscriptionJob → Whisper AI speech-to-text (also dispatches GenerateSummaryJob for AI summaries + title)
  • ConvertCameraToMp4Job → converts webcam overlay WebM to MP4 (5s delay)
Service ▶️ Video Ready for Playback!
Bunny videos: ready when bunny_status === 'ready'. Local videos: ready when isHlsReady() === true. HLS adaptive streaming in any modern browser. Share URL: /api/share/video/{token}/stream
StreamVideoController 1️⃣ startUpload() — Begin Session
POST /api/stream/upload/start
Creates session UUID temp dir: storage/app/temp/stream-uploads/{uuid}/ Checks video quota Creates empty video.webm + camera.webm
StreamVideoController 2️⃣ uploadChunk() — Receive Live Chunks
POST /api/stream/upload/{sessionId}/chunk · Called every 2-5 seconds during recording
Validates chunk_index order Appends in-order to video.webm Out-of-order → saved as pending Separate tracking for camera chunks Type: video | camera
StreamVideoController 3️⃣ completeUpload() — Finalize Recording
POST /api/stream/upload/{sessionId}/complete
Appends remaining pending chunks Remuxes camera WebM (fixes container) Creates Video + VideoZoomSetting records Dispatches all jobs via afterResponse() Cleans up temp session directory
StreamVideoController 🔴 cancelUpload() — Abort Recording
POST /api/stream/upload/{sessionId}/cancel · Cleans up temp files — no Video record is created.
VideoController 1️⃣ store() — Receive Full File Upload
POST /api/videos · Multipart form with title, description, video file
Validates: webm, mp4, mov (max 10 GB) Checks user video quota Probes duration via ffprobe Free users: enforces min/max duration
VideoManager 2️⃣ createVideo() — Persist & Dispatch
Creates Video record via VideoRepository, attaches media file, then dispatches background jobs.
Stores in spatie/media-library (videos collection) Charges monthly recording seconds Reserves workspace storage quota Dispatches: GenerateThumbnailJob Dispatches: GenerateTranscriptionJob Bunny? → UploadToBunnyJob (conversion=completed) Local? → RemuxWebmJob
