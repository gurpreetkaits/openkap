Frontend 1️⃣ User Clicks "Download"
On /videos: User clicks the download icon in the video card's action menu → calls downloadVideoWithAnimation(video) or downloadVideo(video).
On single video page: User clicks "Download" in the options menu (three-dot) or in the action bar below the player → calls handleDownload() → downloadVideo().
Shared page (/share/video/{token}): Visitor clicks download → calls handleSharedDownload() → separate Bunny-only path.
Frontend 2️⃣ API Call: requestDownloadMp4(id)
POST /api/videos/{id}/request-download-mp4 — Sends an authenticated request. The backend determines the best download mode.
Auth: Bearer token Accept: application/json
VideoManager 3️⃣ requestMp4Download(video) — Branching Logic
The backend inspects the video's storage type and status to determine which path to take:
🐰 Bunny CDN (still encoding)
bunny_status is not ready or error
mode: processing HTTP 202

Returns immediately — frontend shows a toast: "Video is still encoding"

🐰 Bunny CDN (ready)
bunny_status === 'ready'
mode: redirect Signed URL (15 min)

Generates a temporary signed proxy URL → GET /api/videos/{id}/download-bunny which streams from Bunny CDN

💾 Local (≤ 5 minutes)
video.duration <= 300s
mode: sync ffmpeg runs synchronously

ffmpeg converts to MP4 on-the-fly (H.264, faststart, max 1080p). File returned as download response and deleted after sending.

💾 Local (> 5 minutes)
video.duration > 300s
mode: async Dispatches ConvertVideoToMp4ForDownloadJob

Job runs in the background. User is notified via the notification bell when ready.

Frontend 4️⃣ Frontend Handles the Response
Based on result.mode:
ModeFrontend Action
redirect Creates an invisible <a> tag pointing to the signed Bunny proxy URL and clicks it. Browser handles the download natively. Shows toast: "Download started!"
sync Receives the MP4 as a Blob. Creates an object URL, triggers a download via a temporary <a> tag, revokes the blob URL. Shows toast: "Download complete!"
processing Shows toast: "Video is still encoding — please try again in a few moments."
async Adds the download to useDownloadTracker. On /videos: animates the thumbnail flying to the notification bell. Shows toast: "Converting to MP4 — check the bell for progress!"
ConvertVideoToMp4ForDownloadJob 5️⃣ Async Path: Background MP4 Conversion
Only for local videos > 5 minutes. Runs in the queue (2 tries, 2 hour timeout).
  • Runs ffmpeg: H.264, max 1080p, AAC 128k audio, faststart moov atom
  • If the video has captions/transcription: burns SRT subtitles into the MP4
  • Output saved to storage/app/mp4-downloads/video_{id}_{timestamp}.mp4
NotificationManager 6️⃣ Download-Ready Notification Created
After successful ffmpeg conversion, the job calls NotificationManager::createDownloadReadyNotification(video, downloadLink).
type: download link: /api/videos/{id}/download-mp4 message: "Your MP4 download is ready"
useDownloadTracker 7️⃣ Polling Detects "Ready" Status
The download tracker polls GET /api/notifications every 8 seconds. When it finds a type: 'download' notification matching the video ID, it transitions the download status from processing to ready. The notification bell badge updates automatically.
Poll interval: 8s Stored in localStorage Stale entries auto-cleaned after 24h
Frontend 8️⃣ User Clicks "Download" in Notification Bell
The notification bell shows a green "Download" button on the ready notification. Clicking it calls triggerDownload() which:
  1. Calls GET /api/videos/{id}/download-mp4
  2. Receives the MP4 as a Blob
  3. Triggers a browser download via a temporary <a> tag
  4. Marks the notification as read
  5. Removes the download from the tracker
File deleted after send deleteFileAfterSend(true)
NotificationManager ❌ Error Path: Conversion Failure
If ffmpeg fails, the job calls createInfoNotification() with an error message. The tracker picks up the failure via the notification text and marks the download status as failed. The temp MP4 file is cleaned up.
type: info status: failed Tries: 2 (with retry)

🔀 requestMp4Download() Decision Tree

🔍 Is this a Bunny CDN video?
$video->isBunnyVideo() && $video->bunny_video_id
YES → Is Bunny encoding complete?
in_array($video->bunny_status, ['ready', 'error'])
✅ Ready
mode: redirect

Creates a temporary signed route: GET /api/videos/{id}/download-bunny (valid 15 min). The proxy endpoint streams the file from Bunny CDN using GuzzleHttp with a signed download URL (resolution capped at 1080p, 1 hour expiry).

⏳ Still encoding
mode: processing

Returns HTTP 202. Frontend shows a toast and the user must try again later. Bunny handles its own encoding pipeline — no local queue needed.

NO → Local video. Is it ≤ 5 minutes?
($video->duration ?? 0) <= 300
✅ ≤ 5 min (Sync)
mode: sync

ffmpeg runs in the same request. Converts WebM → MP4 (H.264, AAC, faststart, max 1080p). If transcript exists, SRT subtitles are burned in. The returned file is deleted after the response is sent.

⏳ > 5 min (Async)
mode: async

ConvertVideoToMp4ForDownloadJob is dispatched to the queue. Same ffmpeg command, but runs non-blocking. User gets notified via the notification bell when ready.

📐 ffmpeg Download Command

Without captions:
ffmpeg -y -threads 1 -i {input} -vf "scale=min(iw,1920):min(ih,1080):force_original_aspect_ratio=decrease,pad=ceil(iw/2)*2:ceil(ih/2)*2" -c:v libx264 -preset fast -crf 22 -maxrate 5M -bufsize 3M -pix_fmt yuv420p -c:a aac -b:a 128k -max_muxing_queue_size 1024 -movflags +faststart {output}
With captions (SRT burned in):
ffmpeg -y -threads 1 -i {input} -i {srt_file} -vf "scale=...,subtitles={srt_file}" ... -c:s mov_text -metadata:s:s:0 language=eng ... {output}

🔔 useDownloadTracker Composable

A shared global state composable that manages the lifecycle of async download conversions across all components.

FeatureDetails
StoragelocalStorage key: openkap_downloads — persists across page refreshes
Poll intervalEvery 8 seconds via setInterval
Poll targetGET /api/notifications?page=1&per_page=20
DetectionLooks for type: 'download' notifications whose link matches /videos/{videoId}/download-mp4
Auto-cleanupEntries older than 24 hours are purged on load
Bunny self-healFor Bunny videos, if the tracker is stuck in processing, it checks Bunny status directly and drops stale entries
Ref countingUses startTracking()/stopTracking() ref-count pattern so polling stops when no components need it
Failure detectionLooks for type: 'info' notifications with "failed" in the message matching the video title

Download State Machine

StateMeaningUI Display
processing Async job is queued or running. Polling active. Orange spinner in notification bell; progress bar in downloads tab
ready Notification found with download link. Conversion complete. Green "Download" button in notification bell; ready badge
failed ffmpeg failed or error notification detected. Red error indicator; notification with error message
MethodEndpointAuthPurpose
POST /api/videos/{id}/request-download-mp4 Bearer token Initiates the download flow. Returns mode: sync | redirect | processing | async
GET /api/videos/{id}/download-mp4 Bearer token Retrieves a previously-converted MP4 file (async path). File is deleted after sending.
GET /api/videos/{id}/download-bunny Signed URL (15 min) Temporary signed proxy that streams the MP4 from Bunny CDN to the browser.
GET /api/bunny/share/{token}/download None (public) Shared video download. Returns a signed Bunny download URL for public share pages.
